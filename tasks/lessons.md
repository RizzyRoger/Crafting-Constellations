# Lessons

- **Spec docs can carry stale template sections.** The Crafting Constellations PDF mixed a "/compute" (AI for students) template with the real mental-health product. Before planning from a doc, skim for sections that contradict the rest and confirm which parts are current. (2026-10-10, corrected by user: "do the mental health one and ignore ai")
- **Firestore listeners must not open before rules can pass.** An optimistic local write (e.g. joining a group) can mount member-only listeners before the server has the membership; the rejected listen tripped an SDK assertion. Gate on `snapshot.metadata.hasPendingWrites === false`.
- **Counter triggers must `update`, never `set` with merge.** A late delete-trigger otherwise resurrects removed parents with negative counts.
- **Vite: mode files beat `.env.local`.** Load order is `.env` → `.env.local` → `.env.[mode]` → `.env.[mode].local`, so a committed `.env.development` overrides real keys in `.env.local` under `vite` dev. Use a separate mode (`vite --mode live`) to run against the real project. Secrets for one mode go in `.env.[mode].local`.
- **Vite: never alias `import.meta.env`.** `const env = import.meta.env` makes the production build inline every `VITE_` value, including ones only read in dev-only branches. Read keys by name (`import.meta.env.VITE_X`). Checked with a canary value grepped in `dist/`.
- **Firebase Functions v2 + ESM: `setGlobalOptions` must run before any function is defined.** `export … from` modules evaluate before the index body, and `onCall`/`onDocument*` capture options when defined. Put the call in its own module imported first, and check `fn.__endpoint` (region, maxInstances) after building.
- **Emulator test runs: never wipe between cases that wait on triggers.** Clearing Firestore fires the previous run's delete triggers late, which move counters in the next run. Give each case fresh ids instead.
- **Ask for the symptom when a bug report is vague.** "There's a problem with reaching out" was really "the recipient couldn't click Accept". I fixed a real but different bug first. Ask what the person saw (which screen, which button, what happened) before choosing a root cause. (2026-10-10, corrected by user)
- **A disabled control needs its reason next to it.** Accept was greyed out for unconfirmed emails with no explanation, so it read as broken. When a rule gates an action, show the reason and the way through, not a silent `disabled`.
- **Check whether a gating relation is symmetric.** "A friend's friend can't reach out; they connect with you first" holds for both people, so neither could ever connect. Before blocking A from acting on B, check what B sees.
- **SVG `feTurbulence stitchTiles` joins up at the filter region, not the image.** The default filter region overhangs the element by 10% on each side, so a 600px tile stitched at 720px and showed seams on every page. Pin the region to the tile (`x='0' y='0' width='100%' height='100%'`) and measure the alpha step across the tile edge against steps inside it (it was 32×; now ordinary noise).
- **Rules judge a query pinned to one document id as a read of that document.** `where(documentId(), '==', id)` plus `status == 'published'` was refused once the item was withdrawn, and the refused listen broke the Firestore client (ca9/b815) for the whole page. To look up writing that may be gone, query on fields the rules can prove (`status == 'published'`, `createdAt == <its time>`) and pick the id from the results; gate on membership so the place itself is readable.
